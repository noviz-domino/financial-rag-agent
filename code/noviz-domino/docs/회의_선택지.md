### 3-1. LLM (답변 생성 / Agent 판단)
| 선택지 | 장점 | 단점 |

| ⭐ A. OpenAI 저가형(예: `gpt-4o-mini` / `gpt-4.1-mini`급) | LangChain 예제가 가장 많음. tool calling이 안정적. 토큰 사용량을 응답에서 바로 얻음 | 유료 |

### 4-1. 청크(Chunk) 형식
| 필드 | 필수 | 설명 |
|---|---|---|
| `chunk_id` | ✅ | 예: `terms06_a017_c0`. 청킹 설정이 같으면 실행할 때마다 같은 ID가 나와야 함 |
| `text` | ✅ | 임베딩하고 LLM에 넣을 본문 |
| `file` | ✅ | PDF 파일명(답변의 출처 표시용) |

| `doc_type` | ✅ | `glossary` / `terms` / `life_guide` / `additional` (scope 필터용) |
| `source_ids` | ✅ ⭐ | 이 청크가 포함하는 정답 근거 ID 목록. **검색 평가의 핵심** |
| `title` | 선택 | 용어명, `제17조(부득이한 인출)`, 상위 제목 등 |
| `strategy` | 선택 | 청킹 전략 이름(`recursive_500_50` 등) |

| 선택지 | 설명 |

| ⭐ A. 구조 청킹은 unit에서 바로 상속, Recursive 청킹은 "청크 텍스트가 겹치는 unit"을 찾아서 부여 | 청킹 방식과 상관없이 평가 가능 |
| B. 페이지 기준으로만 매칭 | 간단하지만 약관·용어집은 한 페이지에 조항이 여러 개라 평가가 부정확해짐 |
