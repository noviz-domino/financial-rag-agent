# PDF 로딩 전략 논의

> 실제 PDF를 측정·렌더링·추출해 보고 정리했어요. ⭐ = 추천, 🔸 = 여유 있으면, ⚠️ = 주의.

## 0. 결론 먼저

1. **표준약관과 용어집은 기본 추출로 충분해요.** A4 세로 1단이고 이미지·도형이 0개예요. 팀원 생각이 맞아요.
2. **실제로 문제가 되는 건 "읽는 순서"예요.** 2쪽을 붙인 펼침면과 2단 본문은 기본 추출을 하면 **왼쪽 줄과 오른쪽 줄이 한 줄로 섞여요**(아래 증거 참고). 이게 청킹보다 먼저 해결해야 할 1순위예요.
3. **이미지·스캔 페이지는 정답 근거와 겹치지 않아요.** 텍스트가 거의 없는 페이지(표지, 간지) 40쪽과 이미지가 면적 50% 이상인 페이지 34쪽 중 **정답 근거 페이지는 0개**예요. 그래서 OCR은 우선순위가 낮아요.
4. **차트는 "축 숫자 노이즈"가 문제예요.** 차트 안의 숫자(`5.0 4.0 3.0 ...`)가 텍스트로 잡혀서 검색 노이즈가 돼요. 그림 제목·단위·자료 출처는 살리고, 축 숫자 덩어리는 걸러 내거나 요약으로 바꾸는 쪽을 추천해요.

### 증거 A: 펼침면을 기본 추출했을 때 (가이드북 p.10)
```

```
→ 페이지를 가로 절반으로 crop하면 정상적으로 읽혀요.

### 증거 B: 2단 본문 + 차트 + 사이드바 (자영업자 p.2)

→ 하지만 **세로 사이드바 글자**(`금 / 융 / 안 / 정 / 상 / 황`)와 **차트 축 숫자**는 여전히 남아요.

## 2. 문제 유형별 선택지

### P1. 펼침면(A4 두 장이 한 페이지)
| 선택지 | 방법 | 장단점 |
|---|---|---|
| ⭐ A. 가로 > 세로이면 `width/2` 지점에서 crop | 코드 몇 줄 | 가이드북·보험약관 모두 정확히 반쪽 구조. 가장 간단함 |
| B. gutter 탐지로 자를 위치를 계산 | P2와 같은 함수 재사용 | 펼침면 가운데가 정확히 반이 아닐 때도 대응 |
| C. 분리하지 않음 | — | ❌ 문장이 섞여서 청킹·임베딩 품질이 크게 떨어짐 |

> ⚠️ **정답 근거 ID와의 관계**: 정답 ID는 `fss-life-guide-pdf-10`처럼 **PDF 페이지 번호** 기준이에요. 반으로 나눠도 `page=10`은 그대로 두고, `half="L"/"R"`와 `printed_page=18/19`를 **추가 메타데이터**로 붙여요. 답안의 `source_locator`에 "인쇄 18쪽"이 나오기 때문에 둘 다 있으면 좋아요.

### P2. 한 페이지 안의 2단 본문
| 선택지 | 방법 | 장단점 |
|---|---|---|
| ⭐ A. 가운데 35~65% 구간에서 글자가 가장 적게 지나가는 x를 gutter로 보고 좌·우 crop | 직접 구현(약 20줄, 테스트 완료) | 의존성 0. 페이지 전체 폭 요소(제목, 각주, 큰 표)가 있으면 그 부분이 잘려 나뉠 수 있음 |
| B. A + "gutter를 가로지르는 줄은 전체 폭 블록으로 따로 처리" | 줄 단위로 위치 판정 | 더 정확하지만 구현이 더 필요 |
| C. PyMuPDF `get_text("blocks")` + 정렬 | 블록 단위 좌표 | 블록 인식이 좋음. ⚠️ AGPL, 설치 필요 |
| D. 레이아웃 분석 모델(docling, Upstage Document Parse 등) | 문서 구조(제목, 본문, 표, 그림)를 인식 | 가장 정확하지만 설치·비용·시간 부담 |
| E. 문서별 수동 설정(이 PDF는 2단) | config에 하드코딩 | 문서가 6개라 현실적인 방법. 자동 판정과 같이 써도 됨 |

### P3. 차트·그래프 (벡터 또는 이미지)
| 선택지 | 방법 | 장단점 |
|---|---|---|
| ⭐ A. **캡션·단위·자료 출처는 유지하고 축 숫자 줄은 제거** | "숫자·기호만 있는 줄"을 규칙으로 걸러 냄 | 간단함. 수치 질문에는 답할 수 없음 |
| B. 차트 영역을 crop 이미지로 만들고 멀티모달 LLM으로 요약 텍스트 생성 → 별도 청크 | `page.crop(bbox).to_image()` → VLM | 차트 내용도 검색 가능. 비용과 시간이 듦(차트 수십 개) |
| C. 그대로 둠 | — | 노이즈 청크가 생김. 기준선으로 비교할 때는 의미 있음 |
| 🔸 D. 차트 텍스트를 따로 모아 `chunk_type="figure"`로 표시 | 메타데이터로 구분 | 실패 분석 때 "차트 질문"을 따로 집계 가능 |

> 💡 차트 영역 찾는 법: 도형(`rects`, `curves`)이 밀집된 bbox, 또는 "그림 III-5", "참고 1-2" 같은 캡션 아래부터 "자료:" 줄까지

### P4. 표
| 선택지 | 방법 | 장단점 |
|---|---|---|
| ⭐ A. `extract_tables()`로 선이 있는 표를 Markdown 표로 변환하고 표 제목·단위·주석을 붙임 | pdfplumber 기본 기능 | 선이 있는 표(자영업자 참고 1-3)에는 잘 동작. ⚠️ 가이드북 표는 빈 칸이 많이 나와서 조정 필요 |
| B. 텍스트 추출 그대로 | — | 행·열 관계가 사라짐 |
| C. 표 영역 이미지 → VLM으로 Markdown 표 변환 | P3-B와 같은 파이프라인 | 정확도가 높고 비용이 듦 |

### P5. 이미지 속 글자 (스캔, 캡처 화면, 이미지 안의 이미지)
| 선택지 | 방법 | 장단점 |
|---|---|---|
| ⭐ A. **이번에는 무시**(텍스트가 없는 페이지는 기록만 남김) | — | 정답 근거와 겹치는 페이지가 0개라 효과 대비 비용이 큼 |
| B. OCR(tesseract + kor, EasyOCR, PaddleOCR) | 페이지 렌더링 → OCR | Windows에서 설치 부담. 장식 이미지 글자까지 잡혀서 노이즈 |
| C. VLM 캡션 | 이미지 → 설명 텍스트 | 골든셋에 이미지 기반 질문을 넣을 때만 의미 있음 |

### P6. 반복 요소 (머리말, 꼬리말, 쪽번호, 워터마크, 사이드바)
| 선택지 | 방법 |
|---|---|
| ⭐ A. 여러 페이지에 반복되는 줄을 자동 제거(같은 문서의 30% 이상 페이지에 나오는 줄) | 예: "이 문서는 한국은행의 자산으로…", "주택연금 백문백답", "사회 첫걸음부터 똑똑하게" |
| ⭐ B. 페이지 가장자리 여백(상하좌우 약 5%)을 crop | 쪽번호, 세로 사이드바 제거 |
| C. 한 글자짜리 줄이 연속되면 세로쓰기로 보고 제거 | `금/융/안/정` 패턴 |

### P7. 각주
| 선택지 | 방법 |
|---|---|
| ⭐ A. 본문과 분리해서 같은 페이지 청크 끝에 `[각주]`로 붙임 | 폰트 크기가 작은 하단 영역 = 각주 |
| B. 그대로 둠 | 본문 중간에 섞일 수 있음(2단이면 특히) |

## 3. 추천 로딩 파이프라인 (⭐ 조합)

```
PDF 페이지
 ├─ ① 크기 판정: 가로 > 세로 → 좌우 반 crop (P1)          → 하위 페이지 L / R
 ├─ ② 여백 crop: 상하좌우 약 5% 제거 (P6-B)
 ├─ ③ 2단 판정: gutter 통과 글자가 적으면 → 단 분리 (P2-A)
 ├─ ④ 표: extract_tables() → Markdown (P4-A), 표 영역은 본문에서 제외
 ├─ ⑤ 텍스트 추출 → 반복 줄 제거 (P6-A) → 숫자만 있는 줄 제거 (P3-A)
 └─ ⑥ 결과 레코드
      {file, page, half, printed_page, column, text, tables[], figure_captions[], n_chars, has_image}
```
- 약관·용어집은 ①~④가 아무 일도 하지 않으므로 **같은 함수 하나로 모든 PDF를 처리**할 수 있어요.
- 문서마다 예외가 있으면 `LOADER_OVERRIDES = {"self_employed_debt_2025.pdf": {"columns": 2}}`처럼 설정으로 처리해요(P2-E).

## 5. 구현 결과 (`src/loader.py`) — 결정: 차트·표까지 전부 처리

### 실행
```bash
python -m src.loader                                   # 전체 → data/processed/pages_v2.jsonl
python -m src.loader --show financial_life_guide.pdf:10   # 한 페이지: 기존 추출 vs 로더 비교
python -m src.check_loader                             # 글자 보존율 + BM25 Hit@k 비교
python -m src.loader --vlm                             # 차트·표 VLM 요약 (OPENAI_API_KEY 또는 GOOGLE_API_KEY 필요)
```

### 처리 단계와 근거가 된 실제 사례
| 단계 | 처리 | 근거 사례 |
|---|---|---|
| 겹쳐 찍힌 글자 복원 | `dedupe_chars()` | 가이드북 굵은 글씨 `1100..55%%` → `10.5%` |
| 펼침면 분리 | 가로 > 세로이면 L/R | 가이드북 41쪽, 보험약관 7쪽 |
| 사이드바 제거 | 같은 x에 **좌우가 비어 있는** 1~2글자가 세로로 4개 이상 | 한국은행 PDF `금/융/안/정/상/황`. 좌우 조건이 없으면 줄 첫 글자(`다.`, `성`)까지 지워짐 |
| 위첨자 제거 | 중간값의 65% 미만 크기 숫자·괄호 | 표 안 `16.5²)` → `16.52)`로 오염되던 문제 |
| 표 → Markdown | 기본 설정 → 실패 시 (세로선 + 텍스트 행) | 가이드북 표는 기본 설정이 빈 칸만 반환 |
| 하위 행 펼치기 | 줄바꿈으로 나뉜 셀을 여러 행으로 | `자산\n금융자산\n부동산` |
| **lossy 표 판정** | 표 영역 원문 대비 셀 속 **한글·숫자를 각각** 90% 미만 보존 → 본문 유지, Markdown 미사용, VLM 대상 | 행 이름 `적립금` 누락. 숫자만 세면 놓침 |
| 단 분리 | gutter를 **가로지르는 줄 수**가 30% 미만이면 2단. 전체 폭 줄은 별도 띠 | 단어 수 기준으로 하면 1단 페이지도 2단으로 오판 |
| 줄 정리 | 쪽번호, `.indd` 인쇄 표시, 머리/꼬리 위치의 반복 줄 제거 | 본문 속 `자료: 한국은행…`까지 지워지지 않도록 위치 제한 |
| 숫자 줄 분리 | 한글이 없고 숫자 위주인 줄 → `figure_lines`(페이지 끝 `[그림·표 수치]`) | 차트 축 숫자와 선 없는 표의 숫자 행은 줄만 보고 구분할 수 없어서 **버리지 않고 뒤로 이동** |
