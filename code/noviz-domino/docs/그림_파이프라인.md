# 그림·표 처리 파이프라인 (OCR·레이아웃 → 필요한 것만 Gemini)

> 원칙: **AI 호출이 가장 비싸다** → 규칙·레이아웃·OCR로 걸러 낸 뒤 남은 그림만 Gemini로 Markdown 변환

## 흐름
```
PDF ─▶ loader.py (레이아웃: 펼침면·단·표·숫자 줄)          비용 0
     ─▶ figures.py 추출
          ├ raster       : 비트맵 이미지 (겹친 이미지는 합쳐서 1개)
          ├ vector_chart : 선·곡선으로 그린 차트/도식 (이미지가 아니라 '이미지만 자르기'로는 놓침)
          └ lossy_table  : 셀 추출에서 값이 빠진 표
        필터: 면적 2% 미만 / 같은 원본 이미지 3회 이상 반복(배너·아이콘) / 글자가 얹힌 배경 이미지 / 렌더링 동일 중복
     ─▶ (옵션) OCR  : raster 의 글자 → 장식 판정 보조 + Gemini 숫자 검증용 참조
     ─▶ (옵션) Gemini: 남은 그림만 PNG → Markdown (캐시: data/cache/gemini_md/)
          └ num_check: Markdown 숫자 중 PDF 텍스트 레이어/OCR 에 실제로 있는 비율 → 낮으면 환각 의심
     ─▶ chunking.py --figures : text / table / figure 청크 + 메타데이터
```

## 실제 수치 (가이드북 + 추가 PDF 7개)
| 단계 | 개수 |
|---|---|
| 원본 비트맵 이미지 | 538 |
| 그림 후보(raster 141+… / vector 69 / lossy 표 126 등) | 415 |
| 장식 제외: 반복 이미지(주택연금 FAQ 배너 등) | −100 |
| 장식 제외: 글자 얹힌 배경 | −19 |
| **Gemini 변환 대상** | **296** |

시행착오에서 얻은 규칙
- **이미지 해시는 원본 스트림으로.** 렌더링 결과로 해시하면 배너 위 글자(질문 번호)가 달라서 같은 배너가 서로 다른 그림이 됨
- **표 안의 선을 먼저 빼고 벡터를 묶기.** 안 그러면 차트와 바로 아래 표가 한 덩어리가 되어 둘 다 사라짐
- **나란한 패널은 2차로 합치고 15pt 확장.** 패널 하나는 페이지의 1.7%라 기준에서 탈락했고, 축 라벨·범례는 그림 바깥에 있음

## 청크 메타데이터 (`data/chunks/structural_1200_fig.jsonl`)
| 필드 | 예시 | 용도 |
|---|---|---|
| `doc_id`, `file`, `doc_title` | `self_employed_debt_2025` | 어떤 문서 |
| `page`, `pages`, `half`, `printed_page` | `2`, `[2]`, `"L"`, `18` | 어느 페이지. 정답 ID는 `page` 기준 |
| `chunk_index` | `3` | 페이지(또는 조항) 안 몇 번째 청크 |
| `content_type` | `text` / `table` / `figure` | 텍스트·표·그림 구분 |
| `figure_kind` | `raster` / `vector_chart` / `lossy_table` | 그림 종류 |
| `source` | `text_layer` / `pdf_table` / `gemini:…` / `ocr` / `caption+text_layer` | 내용을 어디서 얻었나 (신뢰도 판단) |
| `bbox`, `image_path`, `caption` | `data/figures/img/...png` | 원본 그림 위치 → 답변 때 이미지 재확인 가능 |
| `num_check` | `0.92` | Gemini 숫자 검증 |
| `source_ids` | `self_employed_debt_2025-pdf-2` | 평가용 정답 매칭 |

현재 구성: text 1106 / table 57 / figure 69 (Gemini 변환 전이라 figure는 벡터 차트의 텍스트 레이어만 있음)

## 실행
```bash
python -m src.figures                   # 추출만 (비용 0) → data/figures/
python -m src.figures --ocr             # + OCR
python -m src.figures --vlm --limit 5   # Gemini 5개만 시험 (GOOGLE_API_KEY 필요)
python -m src.figures --vlm             # 296개 전체
python -m src.chunking --strategy structural --figures
python -m src.check_chunks structural_1200 structural_1200_fig
```

## 남은 결정
1. **OCR 엔진**: 설치된 것이 없음 (아래 비교)
2. **Gemini API 키**: `.env`에 `GOOGLE_API_KEY=...` (깃에 올리지 않기)
3. 긴 표 청크(최대 2,767자)를 행 단위로 나눌지(헤더 반복) 여부

| OCR 후보 | 한국어 | 설치 | 비고 |
|---|---|---|---|
| RapidOCR (onnxruntime) | 한국어 모델 별도 지정 필요 | `pip` 가벼움, onnxruntime 이미 설치됨 | 기본 모델은 중국어·영어 |
| EasyOCR | ✅ `ko` 지원 | torch 필요(수백 MB) | CPU에서 느림 |
| Tesseract + kor | ✅ | Windows 설치 파일 + 언어 데이터 별도 설치 | 레이아웃이 복잡하면 정확도가 떨어짐 |
| PaddleOCR | ✅ korean 모델 | paddlepaddle 설치가 무거움 | 정확도 좋은 편 |
| 클라우드 OCR (CLOVA, Google Vision) | ✅ 우수 | API 키 | AI 호출과 비슷한 비용 |

## 2차 개선: OCR 라우터 (2026-10-20)

### 왜 필요했나 (실제 측정)
| 문제 | 측정 결과 | 대표 사례 |
|---|---|---|
| 글자를 **도형으로 바꾼 벡터 차트**는 텍스트 레이어가 비어 후보에서 탈락 | 벡터 영역 87개 중 18개 탈락, 그중 5개에 OCR 글자 존재 | 퇴직연금 p.17 "권역별 점유율 추이 / 사업자별 점유율" (막대+원그래프) |
| **화살표**는 작아서(면적 2% 미만) 면적 기준에서 탈락 → 흐름도의 순서 정보 손실 | 작은 이미지 179개 (번호 배지, 화살표, QR, 잘린 그림 조각) | 주택연금 p.41 가입 절차, p.72 재건축 단계표 |
| 3회 이상 반복 이미지를 무조건 제외 | 제외된 100개는 전부 FAQ 제목 배너 (질문 글자는 텍스트 레이어에 있음) | 문제없음. 단, 앞으로를 위해 OCR 확인 추가 |
| 세로 글자를 사이드바로 보고 삭제 | 흐름표의 핵심 라벨까지 삭제 | 주택연금 p.72 "가입 가능 / 가입 불가" |

### 바뀐 규칙
| 대상 | 이전 | 이후 |
|---|---|---|
| 벡터 영역 | 텍스트 레이어 숫자 4개 또는 단어 8개 이상 | 위 조건 **또는 OCR 글자 10자 이상** (`route=ocr_text`) |
| 작은 이미지 | 면적 2% 미만이면 제외 | 3개 이상 모여 있으면 **흐름도 영역**으로 묶어 후보 (`kind=diagram`) |
| 반복 이미지 | 3회 이상이면 제외 | 3회 이상 **이면서 숨은 글자(OCR에만 있는 글자) 15자 미만**일 때만 제외 |
| 작은 무글자 이미지 | 같은 기준 | 면적 5% 미만 + OCR 글자 15자 미만 → 제외 (QR·로고·아이콘) |
| 세로 글자 (`loader.py`) | 삭제 | `[세로] 가입불가`처럼 한 줄로 보존. 매 페이지 반복되는 사이드바는 반복 줄 규칙이 제거 |
| 캡션 | 위 36pt, 없으면 아래의 아무 캡션 | 영역 안 첫 줄 → 위 70pt → 아래는 `자료:/주:`만. 가로는 그림 폭 ±20pt |

### 결과
- 변환 대상 296 → **304** (OCR로 살린 차트 7, 흐름도 4 추가 / QR·로고 3 제외)
- 복구 확인: 퇴직연금 p.17 차트, 주택연금 p.41 절차 흐름도, 자영업자 p.3(**74조각으로 잘린 차트 이미지**)
- 그림·표 참조 링크 34개 **전부 정확** (이전 40개 중 일부 오연결 → 캡션 수정으로 해결)
- 실행 시간: 그림 추출 + OCR 라우터 약 2분 (Windows OCR, 2배 확대)

### OCR 엔진 비교 (`python -m src.ocr_compare`, 정답 = PDF 텍스트 레이어, 205개 자동 채점)
| 엔진 | 1장당 | 글자 재현율 | 글자 정밀도 | 숫자 재현율 |

| EasyOCR ×1 | 2.39초 | 0.813 | 0.920 | 0.641 |
| EasyOCR ×2 | 5.11초 | **0.865** | 0.923 | 0.740 |
| Windows OCR ×1 | 0.12초 | 0.795 | 0.942 | 0.711 |
| **Windows OCR ×2** ⭐ | **0.16초** | 0.852 | **0.950** | **0.766** |

- 라우터 기본값 = **Windows OCR ×2**: 숫자 재현율·정밀도가 가장 높고 EasyOCR ×2보다 약 32배 빠름

### 실행

## Gemini 시험 변환 (gemini-2.5-flash, 같은 그림 5개, 1차 → 2차)

실행: `python -m src.vlm_trial --env <.env 경로> --ids <그림 5개>` · 결과: `data/figures/vlm_trial_v1.md`, `vlm_trial_v2.md`

### 2차에 적용한 개선 4가지 (+1)
| # | 개선 | 이유 (1차에서 발견) |
|---|---|---|
| 1 | 프롬프트: **글자로 적힌 숫자만**, 선 높이로 값 추정 금지, 나머지는 `추세:`로 서술 | 선그래프에서 라벨 없는 연도별 값 28개를 지어냄 |
| 2 | 크롭: 차트 위에 붙은 글자 줄(범례·제목)을 최대 60pt까지 포함 (`grow_up`) | 범례가 잘려 선과 계열 이름을 잘못 연결 |
| 3 | 숫자 검증: 쉼표·마침표 무시, 캡션 숫자 포함, `2017`↔`17` 연도 인정 | OCR이 `228,235`를 `228.235`로 읽어 맞는 답이 감점됨 |
| 4 | 세로 라벨 → 표 연결 (`attach_vertical_labels`): 라벨이 표 높이의 절반 이상 덮으면 `구분` 열, 아니면 캡션에 `[구분: …]` | p.72 "가입 가능/불가"가 표와 분리됨 |
| +1 | 프롬프트: 기관명·항목명은 이미지 글자 그대로 | 2차 중간에 "중소기업은행"을 "IBK기업은행"으로 바꿔 씀 |

### 결과
| 그림 | 1차 숫자 검증 | 2차 숫자 검증 | 사람 대조 결과 (2차) |
|---|---|---|---|
| 값이 빠진 표 `[표 1] 가계신용 추이` | 1.00 | 1.00 | ✅ 모든 값 정확 |
| 화살표 흐름도 (주택연금 p.41) | – | – | ✅ 8단계 모두, 순서 유지 |
| 비트맵 막대그래프 `[그림 1] 연령별 금융채무불이행자` | 0.61 | 0.94 | ✅ 7개 값 모두 정확 (1차도 정확했고 점수만 낮았음) |
| 글자가 도형인 차트 (퇴직연금 p.17) | 0.59 | 0.65 | ✅ 막대 15개·원그래프 8개 값 정확, 기관명 정확. 점수가 낮은 건 기준 OCR이 깨져서 |
| 벡터 선그래프 `그림 Ⅲ-7` | **0.29** | **0.83** | ✅ 지어낸 값 0개 (끝점 라벨 5개만), 범례 정확, 추세 서술 정확 |

- 비용: 5개 기준 입력 약 3,650 / 출력 약 2,500 토큰 (프롬프트가 길어져 1장당 입력 약 480 → 730 토큰)
- 숫자 검증 점수는 **"VLM이 틀림"과 "기준(OCR)이 깨짐"을 구분하지 못해요.** 글자가 도형인 차트처럼 기준이 OCR뿐인 경우는 점수가 낮아도 맞을 수 있어서, 낮은 점수는 "자동 폐기"가 아니라 **"사람 확인 필요" 표시**로 써야 해요.
- 숫자 검증으로 잡히지 않는 오류(기관명 바꿔 쓰기, 추세 서술 오류)가 있었어요 → 프롬프트 규칙으로 줄였지만, 전체 변환 후 표본 검수가 필요해요.
