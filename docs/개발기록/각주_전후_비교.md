## 2. 실험 방법
- 같은 코드·같은 설정(기준: 구조형 1200, 하이브리드 k=5, gemini-2.5-flash, 채점 gemini-2.5-pro)에서 **`data/`만 바꿔** 두 번 실행했어요.

  - 후: D38로 다시 빌드(`build` → 색인 오류(segfault, F7과 같은 증상) → `build --reuse`로 완료)

## 6. 해석과 한계
1. **좋아진 방향은 분명해요.** 각주가 들어간 청크를 본 문항의 점수가 0.18 올랐고, 영향이 없어야 할 114문항은 정확히 그대로였어요(통제가 잘 됨).
2. **크기는 확정적이지 않아요.** 각 조건을 한 번씩만 돌렸고, 직접 영향을 받은 문항이 28개뿐이에요(문항 1개 = 0.036점). 근거 글이 조금만 바뀌어도 AI 답변이 달라지는 흔들림이 있어서 반복 실행(실험 0과 같은 방식)으로 확인하는 게 좋아요.
3. **검색은 손해도 이득도 거의 없어요.** 각주 효과는 검색이 아니라, 찾은 청크 안에 정의가 같이 들어 있어서 **답변을 더 정확히 쓰게 된 것**으로 보여요.
4. **비용은 그대로예요.** 질문당 AI 호출 2.21 → 2.16, 입력 토큰 -1%. 풀이가 붙어 청크가 길어졌지만 재검색이 줄어 상쇄됐어요.
5. 행동 일치가 낮은 건(추가 PDF 0.22~0.25) 각주와 상관없는 F9 문제(answer 를 correct 로 분류)예요.
