## 3. 이어받아 시작하는 법
```bash
git switch main && git pull
git switch {내 GitHub 아이디} 2>/dev/null || git switch -c {내 GitHub 아이디}
git merge main
python -m venv .venv && source .venv/Scripts/activate
pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env            # 처음 한 번, GEMINI_API_KEY 입력
pytest                          # 88개 통과 확인
```

**`data/`(임베딩·색인·그림 설명) 받기** — git에 없어서 둘 중 하나:
- **공유본 받기 (추천, 비용 0)**: [Release `data-baseline`](https://github.com/noviz-domino/financial-rag-agent/releases/tag/data-baseline) (2026-10-21, 136MB: 그림 설명·임베딩 001/2·Chroma 색인·모든 청크 변형)에서 zip을 받아 `python -m src.pipeline.artifacts import {zip 경로} --config configs/baseline.json`
- **없으면**: `python -m src.pipeline.build --config configs/baseline.json --variants all` (그림 설명 약 40분 + 임베딩, 비용 발생)

**공유본 올리기** (`data/`를 만든 사람이 한 번):
```bash
python -m src.pipeline.artifacts export --tag baseline
# 출력되는 gh release create ... 명령을 그대로 실행
```
설정(청킹·임베딩 모델 등)을 바꿔 새로 빌드했다면 다시 export해서 새 태그로 올려요. import는 설정이 다르면 경고하고 멈춰요.

## 4. 작업을 마칠 때 (다음 사람이 이어갈 수 있게)
1. `pytest` 통과 + `bash scripts/check_notebook.sh`로 노트북이 지금 코드로 끝까지 도는지 확인. 함수·설정 이름을 바꿨으면 노트북 호출 칸, 새 실험은 10장, 바뀐 기준값은 설명 글도 같이 고쳐요
2. 결정한 것 → [02_결정_기록.md](02_결정_기록.md), 실험 결과 → [04_실험_결과.md](04_실험_결과.md), 발견한 문제 → [05_실패사례_개선.md](05_실패사례_개선.md), 한 일 → [01_개발_과정.md](01_개발_과정.md)
3. **이 파일의 1·2장 갱신** (끝난 것 ✅, 새로 생긴 할 일 추가, 마지막 갱신 날짜·이름)
4. `data/`를 새로 만들었으면 artifacts export → Release 업로드
