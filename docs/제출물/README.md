## 최종 보고서에 적을 내용

- `사용_데이터와_골든셋.md`: 사용 PDF와 검색 범위, 제공 180문항과 직접 작성 30문항의 구분, 골든셋 원문 검수 방법·작성/검수자, 정답이 검색 색인에 들어가지 않았다는 데이터 구성 설명.
- `실험_비교_결과.md`: 기준 설정, 각 실험에서 바꾼 요소, 실행 ID·코드 커밋·질문 세트, 검색/답변/행동/인용 지표, 시간·호출 수·토큰, 반복 실행의 흔들림, 실패 사례, 최종 선택 이유와 남은 한계. 가짜 AI 결과는 성능 근거로 쓰지 않는다.
- 보고서에는 표·핵심 사례를 정리하고 전체 문항별 원본 JSONL을 붙여 넣지 않는다. 원본 실행 기록의 위치와 Release 링크를 남긴다.

## 큰 파일·실행 기록 공유

`data/`, `runs/`, `dist/`는 Git 추적 대상이 아니다. 새 PC에서도 재현할 수 있도록 데이터 공유 Release 태그와 대응 코드 커밋·설정을 [인계 문서](../개발기록/00_현재_상태와_다음_할일.md)에 적는다.

- 데이터: `python -m src.pipeline.artifacts export --tag <공유이름>`으로 묶고 출력되는 Release 업로드 명령을 실행한다. 노트북의 그림 표시까지 재현하려면 `--with-images`를 사용한다.
- 실행 기록: 필요한 `runs/<실험ID>/` 폴더를 별도로 `dist/runs_<실험ID>.zip`으로 묶어 GitHub Release에 올린다. 현재 `artifacts export`는 `data/`만 묶으므로 실행 기록은 자동 포함되지 않는다.
- 실험 기록 문서에는 Release 링크·zip 파일명·포함된 실행 ID를 남긴다. 키·개인정보가 포함되지 않았는지 확인한다.

최종 자료는 개인 브랜치에서 커밋·푸시 → main PR로 공유한다. 마지막에는 위 다섯 제출 요구사항이 모두 충족됐는지 확인하고, 남은 일이 있으면 인계 문서에 표시한다.
