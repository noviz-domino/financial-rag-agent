# 답변 정확도 기준 후보 비교 계획

2026-10-22 사용자가 정확한 비교를 위해 제공 180문항 전체 실행을 승인했다. 기존 검색 상위 세 설정의 골든셋 결과와 구별한다.

## 고정 조건

- 모든 후보에서 현재 Agent, 생성 gemini-2.5-flash, 채점 gemini-2.5-pro, temperature=0을 유지한다.
- 제공 positive 60, negative 40, life_guide 20, additional 60 = 180문항으로 후보 순위를 정한다. 세트별 검색 범위는 그대로다.
- 15개 후보: baseline, recursive 300/500/800, parent-child 300/400/600, structural 800/1600, vector-only, BM25-only, embed_text 접두어, k=3/4, embedding-2. 기존 단일 요소 변경 설정을 사용하며 모든 조합을 탐색하는 실험은 아니다.
- 단순 반복(exp0)과 모든 후보에 공통 적용하는 Agent(exp3)는 별도 후보로 중복 계산하지 않는다.
- 채점은 각 검색 청크의 전체 텍스트와 모든 페이지 번호를 전달하는 full-retrieved-v2로 통일한다. 앞 400자 절단에 따른 잘못된 환각 판정을 방지하기 위한 변경이다.
- 생성·채점을 문항별 worker에서 실행하고 저장은 입력 순서로 한다. 병렬화는 점수 규칙 변경이 아니다.
- 기존 verify의 숫자 검사·행동 분류 프롬프트·골든셋 정답은 이번 비교 중 바꾸지 않는다.
- 전처리는 기존 데이터와 loading.superscript_ratio=0.65를 유지한다. 각주 위첨자 번호 제거 로직이 적용된 기존 산출물이며 각주 본문 전체 삭제나 제거 전후 비교 실험은 아니다. 작은 실제 숫자까지 제거될 수 있는 F1의 기준 개선도 이번 평가에는 반영하지 않는다.

## 선택 규칙

1. 180문항의 답변 점수 합계(각 0~2)를 내림차순 정렬한다. 평균 점수와 순위는 같다.
2. 동률이면 2점 문항 수 내림차순, 채점 환각 문항 수 오름차순, 생성 입력 토큰 오름차순, 후보명 순서로 정한다.
3. 실행·채점 오류 또는 문항 누락이 있는 후보가 있으면 정상 후보만으로 임의 순위를 확정하지 않고 먼저 오류를 확인한다. 실제 실행 중 recursive 300의 POS049가 원 실행과 동일 설정 재시도에서 모두 잘못된 JSON을 반환했다. 이와 같은 모델 출력 형식 실패는 0점으로 전체 분모에 유지한다. 통신·할당량 오류나 문항 누락은 여전히 순위 확정을 막는다. 원본 점수를 바꾸거나 문항을 제외하지 않는다. 이 처리 근거는 `runs/answer_rank_20261022/output_failure_policy.json`에 별도로 기록한다.
4. 상위 3개를 같은 21문항 골든셋에 각각 1회 적용한다. 후보 선택에는 골든셋 결과를 사용하지 않는다.

골든셋은 앞선 단계에서 이미 사용됐으므로 처음 보는 독립 최종 시험으로 주장하지 않는다. 골든셋 결과를 보고 프롬프트·정답·설정을 튜닝하거나 새 후보를 추가하지 않는다. 과거 실험과 현재 비교 사이에는 Agent 구조 및 인용 처리 차이도 있어 그래프만의 효과를 증명하는 실험이 아니다.

## 실행과 저장

- 명령: `.venv/Scripts/python.exe -u scripts/evaluate_answer_candidates.py --execute --config-workers 3 --workers 8`
- 후보 평가 15 × 180 = 2,700건, 상위 3개 골든셋 3 × 21 = 63건.
- `runs/answer_rank_20261022/manifest.json`: 실행 전 후보·정렬 규칙·모든 소스/설정/질문/정답 해시 고정.
- 같은 폴더의 `configs/`, 후보별 `.log`, `provided_progress.json`, `ranking.json`, `golden_comparison.json`에 진행과 결과를 저장한다.
- 문항별 원본은 `runs/answer_rank_20261022_{provided,golden}_<후보>/`에 저장한다. 기존 실행 기록은 덮어쓰지 않는다.
- 실제 API를 사용한다. 캐시를 사용하며 캐시 적중을 포함한 토큰·시간은 이번 청구액이나 순수한 처리속도와 같지 않다.
- 준비 검증: 관련 근거가 400자 뒤에 있어도 채점 프롬프트에 포함되는 회귀 테스트를 추가했고 전체 94개 테스트가 통과했다.

완료 후 결과 보고서를 남기고 다음 단계 진행 여부를 사용자에게 묻는다.
