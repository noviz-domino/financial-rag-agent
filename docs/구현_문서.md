검색어는 인젝션이 발견되면 `clean_query`, 아니면 원래 질문을 써요(`q_of`).

**분기** (`after_grade` [`:172`](../src/agent/graph.py#L172), 위에서부터 먼저 맞는 것)

1. AI 호출 상한에 걸림 → `abstain`
2. 행동이 `refuse` / `clarify` / `defer_freshness` → 그 노드 (재검색 없음)
3. `sufficient` → `generate`
4. `link_hint` + `agent.expand` + 아직 안 펼침 → `expand` → `generate`
5. 재검색 횟수 < 2 → `rewrite` → `retrieve`
6. 그 밖 → `abstain`

그 밖의 분기:
- `rewrite` 또는 `generate`에서 상한에 걸리면 → `abstain`
- `verify` 통과 → 끝
- `verify` 실패 + 재작성 횟수 < 1 → `generate`
- `verify` 실패, 재작성 이미 함 → `abstain`

- 설정 해시

## 10. 현재 성능 요약

원본과 조건은 [04 실험 결과](개발기록/04_실험_결과.md)에 있어요. 모두 **1회 실행**이고, 채점 AI는 gemini-2.5-pro 하나예요.

| 지표 | 기본 RAG 180 (R7, `full_rag`) | Agent 180 각주 전 (R9, `fn_before_agent180`) | Agent 180 각주 후 (R9, `fn_after_agent180`) |
|---|---|---|---|
| 답변 점수 (0~2) | 1.411 | 1.400 | **1.422** |
| 과다 거절률 | 0.028 | 0.097 | 0.069 |
| 행동 일치 (5묶음) | 0.556 | 0.528 | 0.533 |
| 필수 내용 포함률 | 0.605 | 0.583 | 0.593 |
| 질문당 AI 호출 | 2.0 | 2.21 | 2.16 |

**검색**: 148문항 하이브리드 k=5 Hit@5는 R7 기준 0.946이고, 각주 반영 뒤 0.939예요(오차 ±0.02 안). 설정별 비교는 R3에 있어요. 거기서 구조형 800자가 같은 Hit@5에 토큰 -14%로 효율이 가장 좋았어요.

R7은 코드 `8aab6df` 시점(F14·F15 수정 전)이고, R9는 각주 기능(D38)이 들어간 코드예요. 두 결과는 코드 시점이 달라서, RAG와 Agent의 차이를 확정하려면 실험 3을 같은 코드로 다시 돌려야 해요.
