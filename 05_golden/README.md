# 골든셋 작성·공유 안내

골든셋의 저장 위치는 이 `05_golden/` 폴더다. 팀원마다 6문항, 총 18문항을 작성한다. 유형은 1인당 정의 1 · 조건 비교 1 · 표·차트 해석 1 · 여러 조항 1 · 답변 불가 2다. 기준은 [기획서 7장](../docs/기획서.md)과 [스키마](golden_schema.json)다.

## 파일 구분

| 파일 | 역할 |
|---|---|
| `golden_schema.json` | 필수·선택 필드 설명 |
| `golden_<GitHub아이디>_draft.jsonl` | 개인별 6문항 초안. main에 먼저 공유하여 교차 검수에 사용 |
| `검수용_<GitHub아이디>.md` | 질문·기준 답안·원문 위치·검수 사항·수정/검수 기록을 사람이 읽기 좋게 정리 |
| `golden_set.jsonl` | 교차 검수가 끝난 최종 평가용 문항. 기본 평가기가 읽는 유일한 골든셋 파일 |

현재 [noviz-domino 초안](golden_noviz-domino_draft.jsonl)과 [검수 문서](검수용_noviz-domino.md)가 있다. 6문항 모두 사람의 작성 확정과 교차 검수 전이다. 다른 팀원의 12문항과 최종 18문항 통합은 아직 남아 있다.

## 협업 순서

1. 작성자는 질문·답안·근거 구절·파일명·PDF 쪽·근거 ID·기대 행동을 적는다. 원본 PDF 순서 1부터 쪽을 센다. AI 보조 초안이면 그 사실을 적고 실제 사람이 작성 내용을 확정한다.
2. 개인 브랜치에서 초안과 검수 문서를 커밋·푸시하고 main으로 PR을 올려 머지한다. **초안을 공유하는 PR의 머지는 교차 검수 완료를 뜻하지 않는다.**
3. 다른 팀원은 개인 브랜치에서 아래 명령으로 초안을 받는다. 커밋하지 않은 수정이 있다면 먼저 커밋하거나 임시 보관한다.

   ```bash
   git fetch origin
   git merge origin/main
   ```

4. 작성자가 아닌 검수자가 PDF 원문과 대조하고, 기준 답안·표의 단위/가정·각주·출처·기대 행동과 제공 질문/다른 골든셋과의 의미 중복을 확인한다. 초안 수정과 검수 결과는 자신의 브랜치에서 후속 PR로 올린다.
5. 승인된 문항은 실제 `author`, 작성자와 다른 `reviewer`, `review_status: "reviewed"`, `reviewed_at: "YYYY-MM-DD"`를 기록하고 최종 `golden_set.jsonl`에 합친다. 검수 문서에는 날짜·검수자·통과/수정 필요·수정 이유를 남긴다. 이 검수 메타데이터는 사람의 확인 기록이며 현재 평가기가 자동으로 검수 상태를 판별하지는 않는다.
6. 최종 통합 담당자는 문항 ID 중복 없음, 작성자별 6문항, 유형 배분, 전체 18문항, 필수 필드, 실제 원문 근거를 확인한다. 작성자 코드는 A/B/C처럼 서로 다르게 정한다. `GOLD-A01` 등의 현재 ID는 팀 내 중복이 없는지 확인 후 확정한다.

답변 불가 문항은 이유와 기대하는 되묻기·보류 등의 대응을 기록한다. 스키마에 따라 `expected_source_ids`는 빈 목록으로 두고 `expected_pages`도 빈 목록으로 둔다. 답변 불가 이유를 확인하는 PDF 위치는 `source_file`, `source_pages`, `evidence_quote`에 별도로 남길 수 있다.

초안과 검수 문서는 최종 통합 후에도 이력을 위해 남긴다. 삭제가 필요하면 별도 변경으로 이유를 적고 최종 문항이나 링크를 함께 지우지 않았는지 확인한다. PR의 파일 삭제는 main에도 반영된다.

## 평가와 인계

- 최종 설정을 확정한 뒤 골든셋으로 한 번만 평가한다. 초안이나 검수 중 문항으로 Agent 성능을 측정하거나 설정을 조정하지 않는다.
- 질문·기준 답안은 검색 DB에 넣지 않는다. 최종 평가 파일에 미검수 초안이 들어가지 않게 한다.
- 실행 기록은 `runs/<실험ID>/`, 요약·코드 커밋·설정·실행 ID·해석은 [04_실험_결과.md](../docs/개발기록/04_실험_결과.md)에 남긴다.
- 누가 작성/검수했고 몇 문항이 남았는지는 [인계 문서](../docs/개발기록/00_현재_상태와_다음_할일.md)에 갱신한다. 폴더 안내의 현재 상태도 함께 맞춘다.
